# AI Sana Challenge Hub

Командный проект ProGulSHIK II для HackAlem AI. Представитель бизнеса превращает короткое описание проблемы в понятную задачу для студенческих команд. Система задаёт уточняющие вопросы, помогает собрать карточку, показывает рейтинг готовности и публикует задачу в каталоге. Команды откликаются; бизнес вручную принимает или отклоняет предложения.

**Текущее состояние: подключён интерфейс создания задачи из архива участника 2.** В браузере доступны исходное описание, уточняющие вопросы, редактирование карточки, подтверждение, рейтинг, публикация и предварительный каталог. Экран откликов и выбора команды ещё готовит участник 3; соответствующие серверные методы уже работают.

## Быстрый запуск

Нужен Node.js **22.18 или новее** (встроенный SQLite). В папке проекта:

```sh
npm install
npm start
```

Приложение в браузере: http://127.0.0.1:3001. Интерфейс и API запускаются одной командой. Проверка сервера: http://127.0.0.1:3001/api/health.
Вместо npm можно использовать pnpm: `pnpm install`, `pnpm start`; точные зависимости сохранены в `pnpm-lock.yaml`.
При первом запуске создаётся `data/hub.sqlite` с демонстрационными данными. После перезапуска изменения сохраняются. Повторный запуск не перезаписывает данные.

Для автоматической перезагрузки сервера после изменения кода: `npm run dev:server`.

## Что реализовано

- Создание и редактирование карточек; версия записи защищает от потери чужих изменений.
- Подключённый браузерный редактор из архива `AI_Sana_Frontend.zip`: форма, вопросы, карточка, рейтинг, публикация, список задач и предварительный каталог.
- Минимум три уточняющих вопроса; перенос явных ответов пользователя в карточку.
- Подключение OpenAI Responses API со структурированным ответом, проверкой ответа и ограничением времени ожидания.
- Явный демонстрационный режим без ключа и резервный режим при сбое ИИ.
- Ручное подтверждение полей и публикация; неподтверждённые сведения не дают баллов.
- Рейтинг 0–100 с расшифровкой, уровнями готовности и рекомендациями.
- Общий каталог: сортировка по рейтингу, фильтры по теме и готовности, поиск.
- Профили команд, отклики с идеей, планом, сроком и ссылкой.
- Ручное принятие или отклонение отклика; можно выбрать несколько команд.
- Сохранение в SQLite, валидация запросов и понятные ошибки API.
- 5 исходных черновиков, 5 опубликованных карточек, 5 команд и 5 откликов.

## Основной сценарий

Создать черновик → получить вопросы → ответить → отредактировать предложенную карточку → явно подтвердить поля → опубликовать → отправить предложение команды → вручную принять или отклонить его.

ИИ возвращает предложения и ничего сам не сохраняет. Интерфейс отдельно отправляет отредактированную карточку, подтверждение человека и публикацию. После правки подтверждение изменённых полей снимается, опубликованная карточка возвращается в черновики до повторной публикации. Изменение исходного описания сбрасывает все подтверждения.

## Рейтинг

| Критерий | Баллы |
| --- | ---: |
| Контекст и потребность | 20 (по 10 за поле) |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 10 (по 5 за поле) |

Поле даёт баллы только при заполнении и подтверждении представителем бизнеса. Пустые строки, знаки вопроса и типовые заглушки вроде `TBD` или «не знаю» не учитываются. Название требуется для публикации, но не добавляет баллы.

Уровни: 0–39 — требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Уровень `draft` в рейтинге и статус `draft` карточки — разные понятия. Опубликованная задача с 0 баллов видна всем и принимает отклики.

## Подключение настоящего ИИ

Скопируйте `.env.example` в `.env`. В Windows PowerShell: `Copy-Item .env.example .env`.
В локальном `.env` задайте:

```dotenv
AI_MODE=openai
OPENAI_API_KEY=ваш_ключ_API
OPENAI_MODEL=модель_доступная_вашему_API_аккаунту
```

Перезапустите сервер. По умолчанию настроен `AI_MODE=mock`: работает без внешнего запроса и явно возвращает `mode: "mock"`. При недоступности API, отсутствии ключа, некорректном ответе или таймауте возвращается `mode: "fallback"` с объяснением. Интерфейс должен показывать текущий режим.

Подключение проверено реальным запросом к `gpt-4o-mini`: сервер получил `mode: "openai"`, пять уточняющих вопросов и сведения для карточки примерно за 6 секунд. На полученном ответе отдельно проверен путь от подтверждения первых сведений (40 баллов) до дополнения карточки (100 баллов), публикации, отклика и его принятия. Этот результат относится к одному синтетическому примеру; доступность и время ответа зависят от API-аккаунта и сервиса. Значение модели можно изменить в `.env`.

Промпт находится в `backend/ai.js` (`AI_PROMPT`). Вход: исходное описание, текущая карточка и ответы по полям. Выход провайдера: предложения по полям с подтверждающими дословными цитатами и вопросы. Сервер проверяет JSON, сохраняет приоритет введённых человеком сведений и отбрасывает предложения без подтверждающей цитаты. Окончательное соответствие смысла поля проверяет человек.

Используется [OpenAI Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Запросы отправляются только из серверной части; `.env` исключён из Git.

## Архитектура и технологии

- Node.js, Express 5 — HTTP API.
- Zod 4 — проверка входных данных и ответа ИИ.
- SQLite из `node:sqlite` — локальное сохранение.
- OpenAI Responses API через встроенный `fetch` — опциональный внешний сервис.
- Встроенный `node:test` — автоматические проверки.
- Текущий интерфейс из архива участника 2: HTML, CSS и JavaScript, папка `frontend/`; отдельная сборка не нужна.

```text
backend/
  app.js          API и переходы между состояниями
  schema.js       поля и проверки
  scoring.js      формула рейтинга
  ai.js           промпт, OpenAI и резервный режим
  store.js        SQLite
  seed.js         синтетические данные
  server.js       запуск
  tests/          проверки
frontend/
  index.html      приложение в браузере
  styles.css      оформление участника 2
  js/app.js       редактор и предварительный каталог
  js/http-service.js  преобразование форматов интерфейса и API
shared/
  types.ts        общий формат данных для интерфейса
  api-client.js   готовые функции обращения к API
docs/
  API.md          запросы, ответы, правила интеграции
  TEAM_HANDOFF.md задания двум участникам и промпты их ИИ
scripts/demo.mjs  воспроизводимый сценарий
```

## Как проверить

```sh
npm test
npm run demo
```

Тесты проверяют основной сценарий, повторное подтверждение после правок, конфликты версий, доступность задач с низким рейтингом, принятие нескольких команд, сортировку, сохранение, неверные запросы и сбои ИИ. Отдельно проверяются подключение редактора к серверу и доступность только публичных файлов интерфейса. Тесты ИИ используют имитацию ответа внешнего сервиса, без реальных запросов и расходов API.

Демонстрационный скрипт создаёт временный сервер и базу в памяти, проходит путь от слабого описания до принятого отклика и выводит результаты. Сохранённую базу команды он не меняет. Для защиты команда должна показать этот сценарий в готовом интерфейсе.

## Данные и ограничения

Все демонстрационные компании, контакты, задачи и предложения вымышлены. Адреса `example.test` служат примерами; ссылки на прототипы не ведут к настоящим работам.

Нет регистрации и проверки прав доступа: это локальный демонстрационный сервер. Роль в будущей форме будет переключателем для показа сценария. Нет чата, загрузки файлов, уведомлений, автоматического назначения команд, рекомендаций по профилю или полноценного проектного трекера. Рейтинг проверяет заполнение и подтверждение сведений, а не достоверность или глубину каждого ответа.

Сервер слушает только `127.0.0.1`. Подключённый интерфейс и API доступны на `http://127.0.0.1:3001`; для альтернативного интерфейса также разрешены запросы с `http://localhost:5173` и `http://127.0.0.1:5173`. Для другой конфигурации доступны `HOST`, `PORT`, `CORS_ORIGINS`, `DATABASE_PATH`, `SEED_DEMO` в `.env`. Развёрнутой версии в интернете пока нет.

Интеграция команды: [подключение присланного интерфейса](docs/FRONTEND_INTEGRATION.md), [исходные задания и промпты](docs/TEAM_HANDOFF.md), [API](docs/API.md).
