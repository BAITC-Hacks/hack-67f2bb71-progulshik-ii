# Подключение интерфейса участника 2

Ветка интеграции: `feature/frontend-integration`.

Участник 2 передал архив `AI_Sana_Frontend.zip`. Его редактор использует HTML, CSS и обычный JavaScript. В этой версии сохранены оформление и последовательность экранов. Разработанный ранее сервер остаётся источником карточек, рейтинга и статуса публикации.

## Запуск

Из корня репозитория: `npm install`, затем `npm start`. Открыть http://127.0.0.1:3001.
Отдельный Python-сервер или сборщик для полученного интерфейса не требуется. Корневой сервер отдаёт только файлы из `frontend/`, не весь репозиторий.

В `frontend/js/config.js` выбран `mode: 'http'`, запросы идут на тот же адрес, с которого открыт интерфейс. OpenAI-ключ по-прежнему находится только в серверном `.env`.

## Как связаны форматы

`frontend/js/http-service.js` преобразует формат присланного редактора в контракт из `docs/API.md`:

| В интерфейсе | В API |
| --- | --- |
| `description` | `rawDescription` |
| `data_materials` | `card.data` |
| `expected_result` | `card.expectedResult` |
| `success_criteria` | `card.successCriteria` |
| `interaction_format` | `card.interactionFormat` |
| `rating.total_score` | `rating.score` |

Остальные поля карточки передаются по тем же названиям внутри `card`; тема передаётся отдельно. Рейтинг не рассчитывается в адаптере. Подтверждение отправляется после явного действия пользователя; версия записи берётся из ответа сервера.

Вопросы и ответы незавершённой формы дополнительно сохраняются в браузере. Поля сохранённой карточки, рейтинг и публикация находятся в SQLite. Сервер не хранит отдельную историю вопросов.

Важное согласованное поведение: после сохранения изменений опубликованная карточка становится черновиком. Она возвращается в каталог после подтверждения и повторной публикации. Отдельной неизменяемой опубликованной копии сервер не хранит.

## Проверка в браузере

1. Ввести название и описание бизнес-задачи от 10 символов.
2. Нажать «Уточнить задачу» и ответить на вопросы.
3. Сформировать карточку, отредактировать поля.
4. Поставить флажок подтверждения и нажать «Подтвердить и оценить».
5. Проверить рейтинг и недостающие сведения, при необходимости дополнить и подтвердить снова.
6. Опубликовать и открыть карточку в каталоге.

В локальном приложении пройден сценарий с реальным ИИ на синтетической задаче «Демо: помощник учебного центра»: вопросы, сбор карточки, ручное подтверждение, оценка 80/100, дополнение трёх полей, повторное подтверждение 100/100 и успешная публикация. Этот пример сохранён только в локальной базе; сама база не входит в репозиторий.

При сбое внешнего ИИ сервер возвращает резервные вопросы. Интерфейс должен явно показывать этот режим. При недоступности самого сервера работа не подменяется локальными демоданными.

## Модуль участника 3

Каталог в архиве — предварительный просмотр. Здесь пока нет пользовательских экранов отправки отклика, выбора команды и переключения роли.

Участник 3 продолжает свою работу. Его исходные задания на React сохранены в `TEAM_HANDOFF.md`; после получения модуля владелец проекта согласует его подключение к текущему интерфейсу. Переписывать работающий модуль только из-за отличия библиотек заранее не требуется.

У редактора сохранены точки подключения:

- `window.Sana.editor.newTask()` — открыть новую задачу;
- `window.Sana.editor.openTask(taskId)` — открыть сохранённую задачу;
- `window.Sana.editor.getDraft()` — получить текущий ввод;
- событие `sana:task-published` — обновить каталог после публикации.

Для откликов используются уже существующие серверные методы `/api/teams`, `/api/tasks/:id/proposals`, `/api/proposals/:id`. Их контракт не изменён.
