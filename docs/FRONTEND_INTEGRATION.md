# Устройство интерфейса

Основа редактора получена из `AI_Sana_Frontend.zip` участника команды. В итоговом приложении сохранены его оформление и последовательность создания карточки; добавлены каталог, профили команд, отправка откликов и решения бизнеса. Интерфейс написан на HTML, CSS и обычном JavaScript.

## Запуск и данные

Из корня репозитория: `npm install`, затем `npm start`. Открыть [http://127.0.0.1:3001](http://127.0.0.1:3001). Сервер отдаёт только публичные файлы `frontend/`. Отдельный сервер интерфейса или сборщик не нужен.

В `frontend/js/config.js` выбран `mode: 'http'`: данные загружаются с API того же приложения. `AI_MODE=mock` в серверных настройках меняет только способ подготовки вопросов, а не хранение задач. Режим `demo` старого интерфейса и `DemoService` сохранены как исходная часть редактора и не используются в обычном запуске.

SQLite хранит карточки, подтверждения, публикации, команды и отклики. При сохранении черновика также сохраняется `interview` — исходный текст интервью, вопросы и ответы. Их можно восстановить после переключения задачи или перезапуска. Ещё не отправленный на сервер ввод редактора дополнительно сохраняется в браузере.

## Подключение ИИ через интерфейс

Кнопка **«Настройки ИИ»** открывает окно с полем пароля **«API-ключ OpenAI»**, моделью и действием **«Подключить и проверить»**. Ручное редактирование файлов и перезапуск для этого не нужны. Сервер сначала выполняет один запрос с вымышленной задачей; он расходует средства API. Только успешная проверка меняет активную конфигурацию. Ошибка сохраняет прежнюю. Пустое поле ключа позволяет использовать уже настроенный ключ.

Модуль `backend/ai-runtime.js` управляет активным провайдером. Ключ, полученный из окна, хранится только в памяти сервера до остановки процесса. Он не включается в карточки, интервью, SQLite, `.env`, локальные файлы, cookies или хранилище браузера; API состояния не возвращает ключ. Внешний запрос к OpenAI выполняет сервер, согласно [правилам аутентификации OpenAI](https://developers.openai.com/api/reference/overview#authentication).

Управление настройками разрешено только с этого же компьютера через локальный адрес `localhost`, `127.0.0.1` или `::1`. Конфигурация общая для всех вкладок данного серверного процесса. **«Деморежим»** отключает ИИ и очищает активный ключ в памяти приложения. После перезапуска сервер снова использует конфигурацию запуска; постоянный `.env` остаётся дополнительным способом настройки и не меняется из окна.

## Формат карточки

Адаптер редактора сопоставляет поля с контрактом [API](API.md):

| В редакторе | В API |
| --- | --- |
| `description` | `rawDescription` |
| `data_materials` | `card.data` |
| `expected_result` | `card.expectedResult` |
| `success_criteria` | `card.successCriteria` |
| `interaction_format` | `card.interactionFormat` |
| `rating.total_score` | `rating.score` |

Остальные поля передаются с теми же названиями внутри `card`; тема — отдельно. Рейтинг вычисляет сервер. Подтверждение отправляется после явного действия человека, с актуальной `revision`.

ИИ предлагает сведения, но ничего сам не сохраняет. После сохранения изменения карточки, темы или исходного описания опубликованная задача становится черновиком; отдельной опубликованной копии сервер не хранит. Изменение только `interview` не снимает публикацию и подтверждения. При конфликте версии редактор сохраняет текущий ввод и предлагает загрузить серверную версию или скачать введённые сведения в JSON.

## Навигация и роли

- «Бизнес»: создание/редактирование, задачи рабочего пространства, каталог и «Отклики команд».
- «Команда»: каталог, отправка предложения и «Мои отклики» выбранной команды.
- «Команды»: выбор существующего профиля или создание своего.

Переключатель роли не вводит авторизацию. Все профили и задачи принадлежат одному локальному демонстрационному пространству. Для многопользовательской версии потребуется отдельная модель аккаунтов и серверная проверка прав.

У редактора доступны точки подключения:

- `window.Sana.editor.newTask()` — начать новую карточку;
- `window.Sana.editor.openTask(taskId)` — открыть сохранённую;
- `window.Sana.editor.getDraft()` — получить текущий ввод;
- событие `sana:task-published` — обновить каталог после публикации.

Порядок демонстрации всех экранов приведён в [DEMO.md](DEMO.md). Дальнейшие изменения согласуются с правилами [TEAM_HANDOFF.md](TEAM_HANDOFF.md).
