# Демонстрация на пять минут

Покажите один полный путь: **слабое описание → уточнение → рост рейтинга → публикация → отклик → решение бизнеса**. Все действия выполняются в приложении.

## Подготовка до защиты

- Запустите приложение по [инструкции](JURY_QUICKSTART.md) и откройте его в браузере.
- Для воспроизводимого примера откройте **«Настройки ИИ»** и выберите **«Деморежим»**. В начале честно назовите его демонстрационным режимом.
- Если показываете настоящий ИИ, заранее вставьте собственный ключ в **«Настройки ИИ»** и нажмите **«Подключить и проверить»**. Проверка расходует средства API; файлы редактировать и сервер перезапускать не нужно. Ключ действует до остановки сервера, затем его нужно ввести снова. Не показывайте сам ключ во время защиты.
- Скопируйте тексты ниже в удобный документ. Новую задачу создавайте с уникальным названием, например добавьте время показа.
- Для отклика выберите готовый профиль «Демо: Edu Makers». Все сведения в сценарии вымышлены.

## 0:00–0:30 — проблема и исходный ввод

**Сказать:** «Бизнес часто описывает задачу слишком кратко. Мы помогаем превратить описание в понятную карточку и показываем, чего не хватает, чтобы студенческая команда могла начать работу».

В роли «Бизнес» начните новую задачу:

| Поле | Текст |
| --- | --- |
| Название | Помощник учебного центра — демонстрация |
| Тема | Образование |
| Исходное описание | Мы — вымышленный учебный центр. Администраторы вручную отвечают на повторяющиеся вопросы о курсах. Хотим быстрее находить согласованные ответы. |

Нажмите **«Уточнить задачу»**.

## 0:30–1:20 — вопросы и первая оценка

При новом вводе в режиме `mock` появятся вопросы о потребности, контексте, данных, ожидаемом результате и критериях успеха. Ответьте пока только на первые два:

| Сведения | Ответ |
| --- | --- |
| Потребность | Помочь администраторам быстрее находить согласованные ответы на повторяющиеся вопросы о курсах. |
| Контекст | Администраторы вымышленного учебного центра отвечают на вопросы вручную и ищут сведения в разных таблицах. |

Оставьте остальные ответы пустыми. Нажмите **«Сформировать карточку»**, проверьте название, контекст и потребность. Поставьте флажок подтверждения и нажмите **«Подтвердить и оценить»**.

Ожидаемая оценка при локальной проверке — **20 из 100**: по 10 за подтверждённые содержательные контекст и потребность. Название баллов не добавляет. Покажите расшифровку, источник проверки качества и недостающие поля.

**Сказать:** «Система проверяет содержание каждого поля, а бизнес подтверждает сведения. Только после этого применяются фиксированные веса. Набор случайных букв баллов не приносит».

Если используется настоящий ИИ, вопросы и заполненные из исходного описания поля могут отличаться. Покажите фактическую оценку и её расшифровку; не обещайте те же промежуточные 20 баллов.

## 1:20–2:30 — дополнение и публикация

Дополните поля карточки:

| Поле | Текст |
| --- | --- |
| Пользователи | Два администратора вымышленного учебного центра. |
| Данные и материалы | CSV с 50 синтетическими вопросами и согласованными ответами. |
| Ограничения | Прототип за пять часов; использовать только синтетические данные. |
| Ожидаемый результат | Работающий веб-прототип поиска ответов по нашей таблице. |
| Критерии успеха | Верный ответ минимум на 8 из 10 заранее подготовленных контрольных вопросов. |
| Контакт | demo@example.test |
| Формат взаимодействия | Короткая консультация с представителем центра и итоговая демонстрация. |

После правок прежняя оценка должна уступить место предложению повторно подтвердить карточку. Снова поставьте флажок и нажмите **«Подтвердить и оценить»**. Для приведённых текстов при локальной проверке ожидается **100 из 100**, уровень «Приоритетная». При проверке внешним ИИ покажите фактические замечания и при необходимости уточните соответствующее поле. Нажмите **«Опубликовать»** и подтвердите действие в диалоге.

**Сказать:** «Система показала, каких сведений не хватает. После дополнения выросла готовность задачи и её позиция в каталоге».

## 2:30–3:40 — самостоятельный отклик команды

Откройте **«Каталог»**, найдите опубликованную задачу. Переключитесь в роль **«Команда»**, выберите профиль **«Демо: Edu Makers»** и откройте форму отклика. Заполните:

| Поле | Текст |
| --- | --- |
| Идея | Сделать веб-форму поиска согласованных ответов по CSV с показом подходящего вопроса и ответа. |
| План | Согласовать структуру CSV, добавить поиск, собрать интерфейс и показать результат на десяти контрольных вопросах. |
| Срок | Пять часов на демонстрационный прототип. |
| Ссылка на прототип | https://example.test/edu-demo |

Отправьте отклик и покажите его в **«Мои отклики»**. Ссылка демонстрационная; в реальном предложении команда указывает свой прототип.

**Сказать:** «Команда выбирает задачу сама. Низкая готовность не скрывает задачу и не запрещает отклик».

## 3:40–4:30 — решение бизнеса

Переключитесь в роль **«Бизнес»**, откройте **«Отклики команд»**, найдите новое предложение и нажмите **«Выбрать команду»**. Покажите изменившийся статус.

**Сказать:** «Решение остаётся за бизнесом. Можно принять одну, несколько или ни одной команды. Принятие одного предложения не отклоняет остальные автоматически».

## 4:30–5:00 — результат и передача

Кратко покажите репозиторий и инструкцию запуска.

**Сказать:** «Весь путь работает в одном приложении, данные сохраняются в SQLite. Судьи могут скачать проект и повторить сценарий без API-ключа; для настоящего ИИ можно вставить собственный ключ в окне настроек приложения. Роли здесь демонстрационные. Следующим шагом можно добавить аккаунты и этапы выполнения проекта».

Не тратьте время защиты на установку зависимостей или редактирование настроек. Если внешний ИИ недоступен, интерфейс показывает резервный режим; продолжайте с локальными вопросами. Если сервер остановлен, сначала восстановите запуск — клиент не подменяет ошибки сервера фиктивным успехом.

## Дополнительные ручные сценарии качества

Это сценарии для самостоятельной проверки, а не отчёт об уже выполненных проверках. Используйте отдельную вымышленную задачу, чтобы сохранить карточку основного показа.

1. **Набор букв.** Введите `вфыв` в контекст, `выфвфв` в пользователей, `2вфыв` в данные, `фывыф` в результат и `вфывфв` в критерии успеха. Подтвердите карточку. Эти поля должны получить замечания и 0 баллов; заполнение всех полей таким текстом не должно давать 100.
2. **Короткие допустимые значения.** Для пользователей укажите `Бухгалтеры`, для контакта — `demo@example.test`, для ограничений — `Без ограничений`. Локальные правила должны распознать эти короткие ответы; длина сама по себе не является причиной отказа. Контакт означает корректный формат, а не проверку существования почтового ящика.
3. **Недостаточная конкретика.** Укажите в критериях успеха `Всё должно быть хорошо`. После подтверждения ожидается пояснение о проверяемом условии приёмки и 0 баллов за этот пункт. Замените текст на `Верный ответ минимум на 8 из 10 подготовленных вопросов` и подтвердите снова: баллы за критерий должны появиться.
4. **Правка после высокой оценки.** В подтверждённой карточке замените содержательный ответ на `вфыв`. Прежние 100 баллов не должны оставаться оценкой изменённой карточки. После сохранения подтверждения сброшены; повторное подтверждение должно дать меньший балл и пояснить причину. Открытие каталога не должно возвращать прежние 100.
5. **Публикация с замечаниями.** После явного подтверждения непустых сведений задача с низким рейтингом по-прежнему публикуется и доступна командам. Замечания уменьшают готовность, но не закрывают общий каталог.
6. **Локальный и резервный режимы.** Без ключа подтверждение выполняет локальную проверку и показывает её источник. Если проверка при подключённом ИИ завершится ошибкой или таймаутом, ожидается `fallback`, понятное предупреждение и результат локальных правил. Сам переход в «Деморежим» означает `local`, а не сбой ИИ. Внешний сценарий может расходовать API-кредиты.

Проверка качества оценивает полезность текста для карточки, а не достоверность фактов. Локальные правила не распознают любой возможный бессмысленный текст; ИИ также может ошибаться. На защите не обещайте абсолютной защиты от некачественного ввода.
