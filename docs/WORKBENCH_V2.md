# Рабочий разбор задачи — v2

Ветка: `feature/task-workbench-v2`. База: `b78a825a5379e68e50eeac4c3425b3bdc1b5c65d`.
Этот модуль не меняет формулу рейтинга, SQLite, авторизацию или правила публикации.

## Возможности

На этапе «Карточка» появляются инструменты:

- **Улучшить карточку / Продолжить разбор**: до трёх раундов, пояснения к вопросам, режимы «Дополнение», «Исправление», «Пока неизвестно». При исправлении пользователь вводит полную актуальную версию поля. Короткие неопределённые ответы получают конкретную подсказку; это не оценка качества и не запрос к внешнему ИИ.
- **Сохранить и закрыть**: вопросы, ответы, режимы ответа, выбранные изменения и текущий раунд сохраняются на этом устройстве. Это НЕ серверное сохранение и НЕ синхронизация между компьютерами. Разбор привязан к ID задачи (для нового черновика — к рабочему сеансу) и содержимому исходной карточки. Изменившаяся карточка блокирует перенос старого разбора. Можно скачать его JSON и начать заново.
- **Собрать понятное описание**: отдельный явный вызов ИИ предлагает связные формулировки. Для предложений возвращаются цитаты и идентификаторы источников. Сервер проверяет, что цитаты действительно существуют, отклоняет неизвестные поля, изменение контактов и новые числовые значения без поддержки в цитатах. Эта проверка НЕ доказывает смысловую правильность; требуется ручная проверка и выбор изменений. В локальном/резервном режиме удаляются только повторы абзацев, семантического переписывания нет.
- **Противоречия**: если модель нашла разногласие, показываются две проверенные цитаты и нейтральный вопрос. Автоматическое предложение для этого поля исключается. Полную согласованную формулировку вводит человек. Обнаружение всех противоречий не гарантируется.
- **Критерии приёмки**: действие, наблюдаемый результат, способ проверки и принимающий. Неизвестное явно отмечается «нужно согласовать». Границы MVP: обязательно, желательно, не входит. Результат сначала показывается в сравнении, а не автоматически сохраняется.
- **Отменить улучшение**: локальная история последних трёх применений. Автоматическая отмена блокируется, если после улучшения были другие правки. Отмена возвращает текст в форму, но не восстанавливает право публикации: необходимо отдельное подтверждение.
- **Скачать ТЗ / Скопировать ТЗ**: Markdown текущей формы, явно обозначенный как рабочий экспорт. При недоступном буфере обмена скачивается файл. Экспорт не публикует и не подтверждает задачу.
- **Сравнить отклики** в разделе «Отклики команд»: 2–3 отклика на одну задачу, точные тексты и статусы без рейтинга/назначения победителя. Некорректные ссылки не превращаются в кликабельные URL. Решения остаются в существующем интерфейсе откликов.

## Запуск

Остановить прежний сервер. Скачать ZIP именно этой ветки и распаковать отдельно либо переключить чистую рабочую копию Git на ветку. В корне проекта:

```powershell
node --version
npm.cmd install
npm.cmd start
```

Требование проекта — Node.js 22.18+. Адрес по умолчанию: `http://127.0.0.1:3001`.
Для Windows установка Node.js с npm нужна до выполнения этих команд. Старая копия ZIP не получает изменения автоматически.
Настройки ИИ используются существующие, из памяти сервера/окружения. Ключ в браузерный код или репозиторий не добавляется.
Запросы ИИ выполняются только по действиям пользователя. Закрытие окна не гарантирует остановку уже начавшегося серверного запроса и расхода API-кредитов.

## Архитектура

- `frontend/js/workbench-core.js` — чистые операции объединения, проверки сеанса, критериев, экспорта и сравнения.
- `frontend/js/workbench-ui.js` — новая панель и диалог; заменяет подключение прежнего `interview.js`. Сам старый файл сохранён для обратимости изменения. Общий `app.js` не переписывается.
- `frontend/js/proposal-comparison.js` — сравнение существующих откликов через общий сервис.
- `backend/synthesis.js` — ограниченный контракт и проверка цитат, Structured Outputs и локальный fallback.
- `backend/ai-runtime.js` — новый метод `synthesize` использует текущие серверные настройки.
- `backend/workbench-app.js` — оболочка над существующим Express-приложением; новый `POST /api/workbench/synthesize`, JSON до 256 KiB. Базовые маршруты и статические файлы сохраняются.
- `backend/server.js` — запускает оболочку. Создание базового `createApp` в старых тестах не проверяет новый endpoint: для этого нужен `createWorkbenchApp`.

Контракт запроса: `{rawDescription: string, card: {title, context, need, users, data, constraints, expectedResult, successCriteria, contact, interactionFormat}}`.
Ответ: `{mode, suggestions, conflicts, sources, warnings}`. Endpoint не записывает карточку, не подтверждает её и не меняет рейтинг.
Локальные ключи начинаются с `aisana.workbench.v2:`. Сохранение — удобство, не механизм прав доступа. Переключение роли по-прежнему не является авторизацией. Использовать только обезличенные данные локального MVP.

## Приёмка перед merge

1. Открыть карточку, ответить в разборе, закрыть окно и обновить страницу. Продолжить разбор без потери ответа.
2. Исправить поле, посмотреть сравнение, исключить изменение; убедиться, что оно не переносится.
3. Применить изменение, отменить его, убедиться, что публикация требует подтверждения.
4. Создать критерии приёмки и границы MVP. Проверить явные неизвестные, отсутствие придуманных чисел.
5. С подключённым ИИ собрать связное описание, открыть источники, проверить отрицания/числа/полноту. Исправить результат перед применением.
6. Изменить карточку после сохранённого разбора: старая сессия должна блокировать перенос.
7. Сравнить два предложения по одной задаче. Проверить, что решение о выборе не изменилось.
8. Пройти общий сценарий публикации, отклика и ручного выбора команды; повторно открыть сохранённую задачу.

Публичная переписка по задачам, серверная история всех публикаций и уведомления командам об изменении требований в этот коммит не включены. Локальная отмена не заменяет такую историю.
