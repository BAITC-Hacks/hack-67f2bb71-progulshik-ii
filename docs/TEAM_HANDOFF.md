# Продолжение разработки

Это инструкция для работы с объединённым MVP. Начальная схема разделения на React-модули больше не применяется: полученный от участника редактор использует обычный JavaScript, и остальные экраны подключены к нему. Готовая версия сдаётся через репозиторий с локальным запуском, без хостинга.

## Разделение дальнейших задач

| Направление | Основные файлы |
| --- | --- |
| Редактор, вопросы, карточка и подтверждение | `frontend/js/app.js`, `model.js`, `http-service.js` |
| Каталог, команды, отклики, выбор бизнеса | `frontend/js/collaboration.js`, `frontend/collaboration.css` |
| Сервер, ИИ, рейтинг, данные | `backend/`, `shared/` |
| Окно подключения ИИ и настройки текущего запуска | `frontend/js/ai-settings.js`, `backend/ai-runtime.js` |
| Общая навигация и оформление | `frontend/index.html`, `app.js`, `styles.css` — согласовать владельца до параллельных изменений |
| Инструкция, демонстрация и сдача | `README.md`, `docs/`, `START_WINDOWS.cmd` |

Перед началом новой задачи получите актуальную основную ветку и создайте отдельную рабочую ветку. Не заменяйте весь интерфейс архивом поверх чужих изменений. Сначала согласуйте изменяемые файлы, затем передайте коммит или pull request. Финальная версия для жюри должна находиться в основной ветке.

## Правила, которые сохраняем при расширении

1. Источник данных — API и SQLite. Массивы примеров в интерфейсе не заменяют сохранение на сервере.
2. Готовность задачи и статус публикации различаются. Все опубликованные задачи доступны в каталоге, даже при низком рейтинге.
3. Рейтинг берётся с сервера: баллы получают только подтверждённые поля со статусом качества `valid`. Формула и веса детерминированы; ИИ оценивает содержание, но не назначает число баллов. Формулу не дублируем в новом экране.
4. ИИ возвращает предложение и вопросы, а при подтверждении проверяет содержание всей карточки. Без ИИ или при его ошибке работают локальные правила с явным источником результата. Пользователь проверяет карточку; сохранение, подтверждение и публикация — отдельные действия.
5. При изменении задачи используется свежая `revision`. Конфликт `409` требует сверки с сервером, а не повторной отправки поверх чужой версии.
6. Любое изменение карточки, темы или исходного описания снимает все подтверждения и сохранённый отчёт качества. Интерфейс не показывает прежний итоговый балл как текущий. Если задача опубликована, после сохранения изменений требуется повторная публикация. Сохранение только `interview` сохраняет её текущие подтверждения и публикацию.
7. Отклик связан с существующей командой и содержит идею, план, срок и ссылку HTTP(S). Бизнес может принять несколько предложений. Принятие одного не отклоняет остальные.
8. Роли демонстрационные. Если добавляется регистрация, права нужно проверять на сервере для каждого действия.
9. API-ключи, `.env`, локальная база и `node_modules` не включаются в Git.
10. Ключ из «Настройки ИИ» хранится только в памяти сервера: не добавляйте его в состояние редактора, журналы, cookies, хранилище браузера, SQLite или файлы. Чтение настроек не возвращает ключ. Эти настройки общие для вкладок одной копии сервера и доступны только через локальный адрес с того же компьютера.
11. Новая конфигурация ИИ применяется только после успешного проверочного запроса с вымышленной задачей; при ошибке сохраняется прежняя. Проверка расходует средства API. Переключение в деморежим очищает активный ключ в памяти приложения, но не меняет `.env`; перезапуск восстанавливает конфигурацию запуска.
12. Отчёт качества привязан к версии правил и отпечатку точного содержания карточки. Нельзя повторно использовать отчёт после правок. Чтение задачи и каталога не вызывает ИИ: если отчёт отсутствует или устарел, сервер применяет актуальные локальные правила, включая старые задачи с прежними 100 баллами за формальное заполнение.
13. Низкое качество поля не отменяет просмотр и подтверждение человеком и не запрещает публикацию. Оно уменьшает рейтинг и добавляет пояснение. Не называйте проверку качества проверкой достоверности; локальные эвристики и ИИ имеют ограничения.

## Где искать контракт

- [API.md](API.md): поля, методы, ошибки, рейтинг и переходы состояний.
- `shared/types.ts`: общие типы данных.
- `shared/api-client.js`: клиент, который можно использовать при создании другого интерфейса.
- [FRONTEND_INTEGRATION.md](FRONTEND_INTEGRATION.md): устройство текущего интерфейса и адаптера.

## Что можно добавить следующей версией

- Учётные записи бизнеса и команд, владение задачами и права доступа.
- Загрузку материалов, уведомления и обсуждение задачи.
- Этапы работы и подтверждение выполненных результатов.
- Рекомендации по интересам команды без ограничения общего каталога.

Эти дополнения не нужны для текущего сквозного сценария хакатона. Для подготовки сдачи используйте [запуск для жюри](JURY_QUICKSTART.md) и [пятиминутную демонстрацию](DEMO.md).
